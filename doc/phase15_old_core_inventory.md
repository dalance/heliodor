# Phase 15 付録 A: 旧コア概念インベントリと新コアでの置き場所

この付録の目的は、旧コア (`b0f4668` の `src/core/heliodor_core.veryl`、13,315 行) にある live な概念のすべてについて、新コアでの置き場所が決まっていることを示すことである。移植元を探すときの索引も兼ねる (`doc/phase15_old_core_inventory.md`)。行は M0 survey の 4 分割 (A1-A4) に従い、旧コアのソース順に並べている。

列の読み方:

| 列 | 意味 |
|---|---|
| `#` | `<部>.<連番>`。本文や他章からはこの番号で参照する。 |
| 概念, 旧コア行 | survey が付けた概念名 (英語のまま) と、`b0f4668` での行範囲。行番号の誤りは各部末尾の裏取り訂正にある。 |
| 状態 | survey の判定: `live`, `partially-dead`, `dead`, `debug-only`。裏取りで判定が覆った場合も、この列は書き換えず、新モジュール列と備考で反映する。 |
| 扱い | survey の判定: `carry-over-concept` (概念を移植)、`replaced-by-structure` (新しい構造に置換)、`reused-module-glue` (再利用モジュールの接続)、`drop`、`debug-only`。 |

#### A1 の構造上の観察

- Width is hard-coded at 2 as duplicated slot-0/slot-1 code, never as a loop: s1_* extraction (1434-1490), two c_expander instances (1113, 1118), second predictor ports realised as full SRAM replicas (btb.veryl:58-72, bht.veryl:37-45, ibtb.veryl:44-52), a_s1_* skid fields (600-605), fb_wr1 write (3860-3871), if_*_q1 reads (3952-3960), u_dec2 (4157). A 4-wide front end cannot be had by changing a number; the new core needs block-based extract (lane i starts where lane i-1 ends) and per-fetch-block prediction (blkpred already indexes once per dword).
- Structure-size consts are not honored: FB_DEPTH (literals 4'd8 at 1569/1572, 3-bit pointers 647-649), WF_N (2077, 387-389), FTQ_N (2353, 552-554), SB_N (1107), ASQ_N (asq_valid_q[0] at 1077), RAS DEPTH (ras.veryl header: literals 5'd16/[3:0]); history/index widths 13/55/9 (1293-1301, 1348, 341) are literals that must match module params; pipeline_pkg FETCH_W/RENAME_W/DISPATCH_W/COMMIT_W/ISSUE_W/CDB_N (pipeline_pkg.veryl:12-16,44) are declared and used nowhere.
- Rule-3 violation (prediction not carried with the bundle): Stage-B reads the clocked predictor output registers and relies on them holding the drained bundle's read (1674-1691). PRED_HOLD_FREEZE (1694-1812) patches pt/tgt/kind bits only; spec_ghr shift (7682-7683), spec_ind_hist fold (7697-7698) and fb_ghr_fold (3855, 3870) still read the live, possibly drifted, outputs (inferred accuracy-only).
- Rule-3 violation (training recomputes instead of carrying): TAGE and iBTB train at indices recomputed from committed history (tage.veryl:13-19; 1954; 7607) on the assumption that it equals the fetch-time speculative history. The Stage-A/B split breaks that: bundle N+1 is looked up at Stage-A before bundle N's Stage-B history update lands (doc/cp_predictor_sram_plan.md:317-320 acknowledges the staleness but asserts only the carried-index BHT case is safe). (inferred) systematic lookup/train index mismatch, a candidate for the coremark earlymis doubling at F2 ship (78529fe). Also (inferred) bht o_taken3 is registered (bht.veryl:66-74) so the TAGE altpred input bht_base_pred_c (1935, 1957) is one commit stale.
- Rule-3 violations recorded in history: interrupt epc taken from the speculative front end (if_pc_q/ic_pc) skipped a jal inside the fetch pipe (cc50446, now arch_next_pc_q at 7316); FTB train aliased by one bundle because Stage-A operands were paired with a clocked read of the previous PC (3700-3710); hold-drift stray pred_next retiring on commit lane B (28dbde7, rob.veryl:608-622).
- Live-state reads where identity should be used: s1_same_line reads imem_paddr_w (1536), the translation of F0's current address, not of the extracted dword - under shape-W F0 addresses are dword-aligned so it is always true (inferred); fetch MMU reads live CSRs (4025-4037) and only satp writes, frm/fcsr, FENCE.I, traps and xRET redirect (7710-7790), so PMP/menvcfg writes and SFENCE.VMA (7149, no redirect) do not refetch already-fetched younger instructions (inferred).
- FIFO geometry stands in for identity: the across-dword next word is wf_data[head+1] (1128, 1160) guarded after the fact by head1_seq (1167) and !ext_bypass (1184, bug 7523761); slot-1 next-dword descriptor reads head+1/head+2 (1652-1658, SMP hang 42c7868); ext_buf_mismatch reads head+1/head+2 (2206-2208); soft override tests wf_pc[head+1] (2298-2299). In the new core each fetch-queue entry should carry its PC and a contiguity/expected-successor field, and lanes should take bytes only from entries they can name.
- (inferred) Precise-exception hole introduced by shape-W: a cross-dword straddle (1193-1210, straddle_same_page forced 1 at 1207) and a slot-1 that starts in head+1 (1534-1553) consume wf_data[head+1] without checking wf_ifault/wf_iacc/wf_gstage[head+1] (only head's bits are used, 1260-1263), and the FB forces slot-1 fault bits to 0 (3864-3867). A 32-bit instruction straddling into an unmapped/non-executable page, or a slot-1 instruction in a faulting next dword, would be delivered as garbage without a fault. The old =0 path re-translated pc+2. Needs a directed test; the new core should carry fault status per halfword or per dword and OR it for every op's byte span.
- (inferred) Lane asymmetry with a cause bug: rename lane 1 reads any FB head+1 record (3952-3960), which can be a faulting slot-0 record of a later bundle, but rob_alloc_entry2 forces ifault_gstage/gpa to 0 (4905-4907) on the premise 'slot-1 shares slot-0's page', which holds for fetch slot-1, not rename lane 1. dec_op2_eligible checks dec_op2.illegal but not if_ifault_q1, so a guest instruction page fault renamed on lane 1 would be reported as cause 12 without htval.
- (inferred) ext_taken_redir decides the mismatch against ext_eff_next (2201, 2206-2208) but re-steers pc_pred/blkpred/pc_fetch_q to ext_next_pc (2421, 2836, 2958-2959), which under PRED_OVERRIDE is built from the previous bundle's clocked prediction (the very staleness 2193-2199 describes); f0_diverged then recovers. Rare at baseline (ext_taken_redir ~0 per 2557-2558).
- One mechanism, many sites: the front-end redirect priority (commit > early > hard override > l0_redir > ext_taken_redir > f0_diverged) is restated in about ten places with different membership (2008-2017, 2393, 2417-2423, 2804-2846, 2865-2874, 2920-2969, 3518, 3568-3576, 3639, 3830). Global history is split across 1290-1301, 1295, 1946, 640/3855/3870 and 7622-7695; indirect history across 1348, 1906 and 7600-7708; fetch fault metadata is copied five times (wf_push_*_q, wf_*, ic_*, a_*, fb_*, if_*).
- Sidebands vs bus: the WORD FIFO PC/fault/descriptor sidebands are correctly registered with the sync-read data (wf_push_*_q, 2870-2887), but the icache stall exists in two timings that must be used in the right places (F0 on combinational icache_stall_comb, push on registered icache_stall; 2081-2084, bug 78355eb); wf_push_dword uses icache_rdata_next without its valid on an implicit dword-alignment contract (1140, icache.veryl:107-117); produce_q (1796) aligns predictions by timing rather than by tag.
- Combinational coupling from rename into fetch: fb_free (1572) includes fb_pop2 = rename_fire2 (4822), which depends on decode of FB head+1 and on IQ/free-list/ROB readiness, and fb_free gates slot-1 production, the slot-1 take and the skid drain (1582, 1672, 1775). The comment at 1689-1691 records a spurious combinational loop through dead FETCH_REG=0 terms. fb_pop duplicates rename_fire and must stay identical (1556-1557, 1564 vs 4650). Valid/ready with registered credit would remove both.
- Correctness rests on a commit-time backstop: the front end may record any pred_next for any op, including non-control ops (7523761, f2a2046, 28dbde7), and correctness depends on the slot-0-only commit check c_bp_mispredict plus ROB lane-B guards. The new core should state the contract explicitly (every op carries its predicted successor; control ops are validated at execute, all ops are covered by a fetch-stream invariant) and keep the f2a2046 'divergence trap' (pred_next == next committed PC) as a permanent assertion.
- Golden-model hazard: the frozen old core's retire trace contains a synthesized instruction page fault after the first S/VS-mode csrw satp enabling Sv39 (inject_fake_ifault 7050-7058) and uses a lazy satp shadow (699-710, 7164-7187). A spec-correct new core will diverge at that point in the 1-hart Linux lockstep; the comparator or the new core must account for it.

#### A2 の構造上の観察

- Forward-declaration sprawl: 4196-4628 and 4942-5100 are mostly declarations of signals driven 3,000-8,000 lines later (lsr_capture 10672, mshr_capture 11418, issue2_fire 11354, store_pretx_valid 9224, m_pa_q 11913, amo_fetch_hold 9519, commit2_fire 8460). The design rationale for the LSR, MSHR, M-stage, AMO handshakes, atomic commit capture, reservation and SC/AMO watches lives in these declaration comments, far from the logic, because an instance must see a var before it is used.
- Rule-3 violations (identity or state read live instead of carried with the op): cdb_dest_is_fp picks per-source flags by mux priority (5164; three recorded bugs 4240-4252, 5131-5143, 5151-5156); i_cdb_fault_gstage/gpa use the live dmem_mmu_gstage/gpa for non-LSU winners (6546-6547); store_pretx_pa from a live TLB probe written at cdb.rob_idx (ROB port 6522-6524, logic 9224); int_div_cdb re-reads pdst/rob_idx/has_rd from the live IQ output (5516-5520); LQ record PA guessed from the LSR occupant (6762, 6768); AMO/CSR/VU execute only when rob_idx == live rob_head_idx (iq_int.veryl 425-428, vector_unit.veryl 2377), with PRF ports rd7/rd8/fp rd5 relying on it; interrupt policy reads live rob_size (4637-4650); every squash recomputes age against the live head (5390-5405, iq_int.veryl 1032, iq_fp.veryl 274, vector_unit.veryl 2589, load_queue).
- Sidebands not registered with their bus: CdbBus has no destination register class, fflags, vxsat, vset/vstart, G-stage/GPA or PA fields, so they travel beside it (cdb_dest_is_fp 5164, i_cdb_fflags 6554-6555, VU sidebands 6558-6566, gstage 6546-6547, store_pretx 6522-6524, rob_cdb_is_lfault 6536/9688, i_cdb_redir_fix 6711-6712). CdbBus fields are also overloaded: store_addr/store_funct3 carry the load VA/size for LQ records, and mispredict is a stale flag nobody reads (6618, 12385-12387).

#### A3 の構造上の観察

- The redirect cause list exists twice and the copies disagree. The redirect always_ff (7714-7793) has 12 arms; commit_redirect (8451), which kills commit slot 1, claims to 'mirror every arm' but omits commit_csrw_frm. The frm arm came in c9d31e0 without an update to commit_redirect. The vector-store arm is covered separately by the ROB (rob.veryl:623). (inferred) A csrw frm/fcsr at the head with a slot-1-eligible head+1 retires both ops, then redirects to c_pc+4 and executes head+1 a second time. The replay conditions are also inlined three times (7729, 7738, 7745) away from their defining lets (8402, 6324, 6312). The new core needs one cause-encoder function.
- Replay is not uniformly 'not a retire'. rob_commit_ack (6402) excludes commit_load_replay and commit_amo_replay but not commit_sc_replay. A poisoned SC commits its rd (rat_commit_en 6958), pushes the free list, emits a retire-trace entry (7887) and counts toward minstret, then is re-fetched by the redirect (7729-7737). #### A4 の構造上の観察

- The task brief says 'a missing load stalls the load pipe (mshr_plain_load = 1'b0)'. That is only half true at b0f4668. The issue-side capture is dead (11409), but LSR_MSHR_B=1 (11453, shipped in 2319734) hands a missing LSR load to a 2-entry MSHR at Stage B and frees the LSR, so up to two misses are non-blocking. The LSR still blocks when both entries are busy, when the load is ineligible (FP, uncached, cross-dword, forwarded bytes, SB overlap; 11575-11577), or while the dcache fills its own line (QUE_SCOPE=0, 11619). Below that, the dcache has a single fill FSM (MSHR_N=1, dcache.veryl:452), and an armed replay blocks all load capture and drive (10671, 10676, 12683-12687).
- Slot asymmetry, now dead weight: the whole pipe-1 load path (sbg* 10261-10407, dc_*2 10566-10584, dmem_*2_m 11152-11153/11181, m_*2_q 11946-11948, ld2_complete 11349) is dead at runtime. iq_int FRONT_PIPE=1 never selects loads for slot 1 (iq_int.veryl:533-550), and dcache S3_SLOT1=1 forces o_hit2=0 (dcache.veryl:3112). Neither folds inside the core, so all of it is still built. The slot-1 SB forward twin also lacks the drain shadow (10271-10286 vs 10076-10081), so naively reviving it would reopen the S20R/Block-T drain window.
- Live slot/lane asymmetry: only writeback lane 0 carries fault sidebands and the FP register-file route, so faulting and FP loads must wait for lane 0 below fpu/mshr/int_div/alu (11668-11674). Plain loads take lane 1 unconditionally and pipe 1 yields to them (issue2_fire, 11354). MSHR completion is lane-0 only (12015-12019), which is why FP loads are excluded from the non-blocking path (11576).
- One dcache CPU port is arbitrated through per-requester yield lists spread across the file, not by a module. Requesters: lsr_drive (10676), replay_drive (10651-10652), asq_dr_port_ok (10859-10860), PTW live bypass (11102, 11126), amo_commit_live (10763), M-stage (11102-11153), VU (core_dmem mux 9167-9172, vu_mem_idle 11324), store_drive (9144). The final priority is the i_addr ternary at 11191 and the OR at 11206. The lists are not symmetric: lsr_drive has no m_load_rd_busy (justified by a probe, 10646-10649), and replay_drive lacked the ASQ terms until a litmus failure (10626-10639). Probes P1-P4 (11154-11180) exist because exclusivity is not structural. The new core needs one arbiter per memory port with explicit grants.
- The M-stage register has no enable: m_pa_q = dmu_dmem_addr every cycle (11913), and all m_* fields likewise (11912-11949). Any cycle's MMU output therefore becomes the next cycle's dcache address, under whatever control the consumer latched. The SQ_RETRY refutation states this outright: 'there is no free cycle on this port' (9236-9248). (inferred) A plain uncached load that is blocked from capture can still produce an M-stage uncached read (m_unc_q 11931; 10640-10642 lists 'an uncached load whose lsr_capture was blocked'). This needs checking before the design doc claims MMIO side-effect safety for the old core.
- Rule-3 class, fill ownership by inference: o_miss_valid used to be read as 'the fill belongs to whoever drives the port this cycle', which is false under DCACHE_SYNC_READ. It was fixed with explicit address compares in replay_claim (11999-12003) and mshr_cap_b_own (11662-11666). The dcache could also pulse o_miss_valid twice per fill (dcache.veryl:2879-2898). The new core should carry an MSHR id with the request and its response.
- Rule-3 violations at commit: the ASQ source operand is read from arch_regs[rs2] at the head (10993-10997, same idiom as cas_q_new_hi at 8769). The AMO commit presence gate picks the watch by comparing rob_commit_idx with stored watch tags (10799-10801); its history includes an SC that checked the AMO watch and lost its write while reporting success (10784-10798). ASQ entry fields come from c_instr at the head (11038-11042).
- Rule-3 violations around early redirect: early mispredict reads the prediction back from the ROB (rob_pred_next_pc[rob_idx], 12405-12408) instead of carrying it with the op, and rewrites the ROB copy (redir_fix, 12450-12455) so the op will not redirect again at commit. The liveness gate em0_live (12393-12404) exists because wrong-path ops can still issue from the IQ with a dead rob_idx; ops carry no kill tag or epoch.
- Relative-age squash against the live rob_head_idx is repeated with hand-written widths: mshra/mshrb/s10_early_age (11528-11532), lsr_age (11543), em0/em1_age with {3'b000, age} <: rob_size (12401-12404), and a 5'd0 reset of early_redir_idx_q (12459). All of these should go through the single centralized wrap/age-compare helper the Phase 15 goals require.
- Sidebands not registered with their bus: (a) o_dmem_wstrb_hi and o_dmem_wdata_hi (12340-12341) come from the live dc_st_wstrb_hi / st_wdata_hi, while at MEM_PIPE=1 the lo write they pair with lands one cycle later from m_wen_q (11135, 11940). The SoC applies the hi write alongside any DRAM write (heliodor_soc.veryl:524, 580), so correctness depends on store_drive staying high into the retire cycle (inferred, not verified). (b) i_wen_excl_q = c_is_cas_q (11199, 8814) is driven live from the head rather than through the M-stage; it is safe only because AMO commit writes bypass the M-stage (amo_commit_live). (c) The LSR's PA reaches the load queue by matching lsr_rob_idx_q against the writeback rob_idx (6762-6772), not on the writeback bus.
- Not actually parametric: SB_N=4 is declared but sb_full==4'd4 (1107), the shift loop is 0..3 (9915), and indices are logic<2> (9810, 9926). ASQ_N=1, but every access indexes [0] (10893-10898, 11036-11044). The MSHR file is two hand-unrolled entries a/b with A always winning alloc, replay and writeback (10599, 12018, 12050-12126). The drain urgency watermark (sb_cnt>=3, 10738) and the load-issue hold (9361) are literals. The LQ instance hard-codes ROB_DEPTH 32 and LQ_N 32 (6773-6778).
- Duplicated logic: the load-size decode appears four times (9839, 10555-10563, 10572-10580, 10678-10680); the MSHR load extension (12139-12151) duplicates alu_wrap's ld_* select; the ASQ RMW ALU (10958-10991) duplicates alu_wrap's AMO compute; the same SB-overlap scan shape appears five times (sb_ld_ovl 9852, sb_st_ovl 9870, sb_walk_ovl 9407, sb_mshra/b_ovl 9474, lsr_sb_ovl 11563); the SB forward layer is 16 copy-pasted per-byte always_comb blocks (10072-10247, 10271-10407) written that way to dodge a Veryl comb-loop diagnostic (10057-10058).
- The store-to-load forward mechanism is split by address space and by place. The uncommitted half (ROB, 8008-8125) compares VAs (FWD_PA=0 at 8039); the committed half (SB, 10063) compares PAs; they are merged at 10248-10260. Because the SB half works per byte on PA+p, it is wrong across a page under VM, so load_blocks_on_store has a page-edge hold (9352, 9359). A unified PA-keyed LSQ forward replaces all of this.
- The SB visibility contract is spread over four places: shadow registers (10007-10030), sb_empty_eff (10031-10040, rationale 1009-1024), forward-layer shadow arms (10076-10081, repeated per byte), and the raw-vs-effective split for resource questions (9798, 10737). The underlying hazard is a snapshot skew: Stage A reads the array, Stage B evaluates the forward net (9970-9991). The new LSQ should state entry lifetime against named load-pipeline stages, so that adding a stage is a local, checked change.
- The atomic store queue is spread across the whole file: declarations 1028-1090; class and retire relaxation 6380-6418; store_drive/fast_store blocks (9144, 8838); load_blocks_on_store (9353-9358); entry, drain and RMW 10803-11102; M-stage write mask 11940; dcache chk3 borrow 11299. The MSHR/replay mechanism is spread similarly: declarations 4255-4320; issue gates 5164, 5253, 5321, 5638; ROB/LQ record ports 6580-6583 and 6810-6815; replay 10585-10652; capture/handoff 11356-11667; FSM and writeback 11983-12213. The LSR: declarations 4334-4389; u_lsu 5432; LQ PA match 6762-6772; forward age 8009; control 10654-10682 and 11534-11883.
- Early mispredict detection and the S8.E early-redirect register (12377-12468) control the front end (2015, 2418, 2815, 2927, 3571), RAT restore (5716) and the ROB (6711), but live at the LSU/census tail of the file. In the new core they belong in a Recovery/Redirect module.
- Two memory-system configurations are both live. Bare testbench harnesses (including the arch suite, tb/test_arch_common.veryl:95-99) run with ID_SPLIT=0 and COHERENT_IFETCH=0, so the shared ic_route arbiter (12245) and the dcache flush sweep (6368, 11279) are live there with PMA_FAULT=1. Both SoCs use ID_SPLIT=1 and COHERENT_IFETCH=1 (heliodor_soc.veryl:343, 346; heliodor_soc_smp.veryl:718, 722). The new core inherits this split if it reuses tb/ unchanged.
- Harness and test artifacts sit inside the core datapath: tohost pages are forced write-through (9766, 10546, plus 8832, 8873-8875, 8894-8895, 9137-9138), and the DRAM-window/PMA literals are repeated about 10 times. The new core should take these from one PMA package function parameterized by the SoC.
- Comb-loop traps: Veryl's loop check is structural and does not fold constants, so dead arms still close loops. Several blocks had to be written as const-guarded statements: the MEM_PIPE dead arms (11114-11120), LSR_B2B (11762-11769, where 230/252 tests failed before), the drain shadow and SB_EMPTY_EFF (9998-9999, 10031), and the ASQ write-enable mux (11056-11060). A core without bit knobs avoids this class.
- Interfaces of reused modules that the new core must respect or rebuild. dmem_mmu: combinational same-cycle translate, one shared address output for walk and data, o_busy stalls the requester, the PTW reads through the dcache (dmem_mmu.veryl:208-237). dcache: one CPU read port plus a store-drain port that any i_wen blocks (dcache.veryl:1414); i_ren must be held to keep a miss's bus request (2872-2875); o_stall ORs many reasons (3304); o_miss_valid is a fill-start pulse, IDLE-gated so it fires once per fill (2898); presence ports chk1/2/3 and eviction-event ports feed the core's reservation, watches and CoRR poison. mem_ctrl STREAM: 8 beats serving buf[addr[5:3]], which the I-PTW FSM relies on (12275-12312).
- Removed bubbles that turned out to be protection (memory note feedback_removed_bubble_was_protection): LSR_B2B exposed the drain-ack/Stage-A collision (11790-11803), and STORE_NOPORT alone wedged the N=2 boot (9113-9118). Both were closed by the drain shadow, not by restoring the bubble. Lesson for the new design: any stage overlap in the load pipeline needs an explicit visibility contract with the store buffer.
